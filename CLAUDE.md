# Video Studio

## What this is

A local application that Claude operates to turn a script or idea into a
finished narrated video in the Ink Stick 2D cartoon style. Claude draws
every picture as code. Owner: Biku.
Plan: Video-Studio-Build-Plan-v5.md. Style: styles/ink-stick/guide.md.
Build progress: BUILD-STATUS.md (read it first in every session).

## Ground rules

1. Everything runs locally. No paid service and no API key is required for a complete video.
2. Claude draws everything. All visuals are vector shapes written in code following the style guide. No image-generation service, no traced or downloaded artwork.
3. Engine and content are separate. A video run writes data files only. It never edits engine code. Engine changes happen only through `/improve`.
4. The storyboard file is the single source of truth for a video.
5. The style is binding. Every visual value comes from `styles/ink-stick/tokens.json`. Never hard-code a color, line weight or proportion in a component.
6. Never overwrite a delivered output. New renders get a new version number.
7. Every stage can be re-run alone and skips work whose inputs have not changed.
8. Plain-language reporting. End every run and every phase with a short summary: what was made, where it is, what Biku needs to decide.
9. Build status. Keep `BUILD-STATUS.md` at the project root: current phase, what is done, what is next, open problems. Update it at the end of every phase and before any session is likely to end. A new session starts by reading it.
10. Run budget. A normal video run should finish in about 30 minutes. If it is heading past 45 minutes, stop and report why. During the build, finish each phase in as few sessions as possible and stop at checkpoints.
11. Verify before you build. Confirm current install commands and Claude Code features in the official docs first.
12. Read only what the run needs: CLAUDE.md, the general playbook, the format playbook, the style playbook, tokens and the brand file.
13. Original designs only. The reference images define a style, not characters to copy. Do not copy any specific channel's characters, mascots, logos or branding.
14. No em dashes in any text the application writes for viewers.

## Operating the studio

Script modes: as-is (never change a word), refine (keep story and facts,
list changes), original (research and write).
Run: understand -> script -> shot plan -> library check -> voice -> music ->
sfx -> mix -> stills -> style check -> preview -> final render -> review
New assets: search library/index.json first, then draw, look, fix, save.

## The opening of every video

Biku's rule (2026-10-11), for every video: the viewer must know what the video is about within the first three seconds.

1. Seconds 0 to 3: the narrator asks one clear question, and the same question appears as big text on screen. The movie scene is already visible behind the text.
2. Seconds 3 to 10: one line that raises the stakes or promises a surprise.

The question:

- 12 words or fewer.
- About "you", or about something everyone has seen.
- No specialist words (for a game theory video: no "prisoner's dilemma", "Nash" or "equilibrium").
- It is the real question the video answers, and the ending answers it.
- It does not start with "In this video", "Did you know", "Have you ever wondered" or "Imagine".

How: the question is the first line of the script and the stakes line the second. The big text is the first shot's `overlay` of kind `words` (up to three short lines, one in gold with `stress`), over a shot of the scene with no face under it. When a script of his does not open this way, write the two lines from it, show them to him, and build only when he has approved them (how it was done for The Dollar Auction; that this holds for every as-is script is Claude's reading). The worked example is the opening of `runs/2026-10-11-dollar-auction/`.

**Game theory videos open differently** (Biku, 2026-10-18: the opening questions were "so weird that no one can relate"; "it should always be stories with mystery"). For the format `dilemma-story` the first 3 seconds show the story's strangest moment (a man throwing a hundred dollars into a river), with one line of at most 12 words that states it plainly, as big words over the scene: no question. The second line makes it stranger or promises more, and the reveal answers the mystery exactly. The question rule above still holds for every other kind of video.

## The game theory cast (The Dilemma Table)

These rules hold for game theory videos and scripts only. Any other video is free of them (Biku, 2026-10-11).

- The Cheat, the Saint and the Copycat are a fixed cast. At least two of them appear in every game theory video.
- They never change look, colours, accessory or voice between videos.
- Always load them from the library. Never redraw them from scratch.
- You, the silent figure in the green cap, is the viewer's own figure. He stays exactly as he is and never speaks.
- The Trainer (grey suit, plain gold tie, neat dark hair; `characters/trainer.json`, voice `trainer`) runs every game: he stands in the room, is friendly to the player and tells the camera the truth. He is part of this cast and keeps his look and voice, and he is not one of the two players the rule above asks for. Biku picked his look ("look 3") and his voice ("voice 1") on 2026-10-11. The card read near the end is spoken by the Leak (`voices/leak.json`), which he kept.

How: in the storyboard set `"series": "game-theory"` and cast them by card (`"card": "cheat"`, `"saint"`, `"copycat"`, `"you"`), with no `look` and no `voice` of the video's own. The storyboard check refuses a game theory video with fewer than two of the three, and one that gives a cast member another voice. Their cards are `characters/<id>.json` (look, voice, approved faces and poses, and the poses that are theirs), their pictures are in `characters/sheets/`, their voices are `voices/cheat.json`, `saint.json` and `copycat.json`. A change to any of them is Biku's to ask for, and raises the card's version.

A game theory video uses the format `dilemma` (`formats/dilemma.json`), the page `brands/dilemma-table.json` and the writing rules `prompts/dilemma.md`; `npm run script -- new --format=dilemma` picks the page by itself. How one is told, filmed and scored is in `knowledge/playbooks/formats/dilemma.md` (the six beats, the dark room, one picture for one job, the sound, lessons L-0038 and L-0039). Read a new script against that page before building, and tell him where it breaks instead of building over it. All of it is this niche's own: no other kind of video is bound by it.

From 2026-10-17 every new game theory video is one kind, a story that is a mystery, a thriller and a little cynical at once (Biku: "all should be like a mystery, cynical and thriller combined", "no random words ... everything should be understandable"): the format `dilemma-story` on the same page, the writing rules `prompts/dilemma-story.md` (v4.0, the story edition: a short everyday story with a mystery, opening on its strangest moment, the real game or experiment told only at the end; every explaining line shown on screen as it is said), the story finder `prompts/dilemma-topics.md` (v4.0), how it is filmed in `knowledge/playbooks/formats/dilemma-story.md`. The older shapes below stay for the videos made in them.

From 2026-10-22 the channel is being remade **the Kurzgesagt way** (Biku: "put your everything to make the dilemma channel the best"; he may hand What's the Catch? to someone else): explainers of the hidden rules of why people do what they do, every topic **true** (a real event, experiment or pattern in nature, with sources), opening on its strangest moment, the rule shown played out by the cast, often hundreds of them at once in an arena. The research, the direction and what is still to make (a look test, the arena, the script guide and format) are in `knowledge/playbooks/formats/dilemma-explainer.md`; the topic finder is `prompts/dilemma-topics.md` v5.0. The story edition below stays for the videos made in it.

Game theory thrillers are mixed in with these videos (Biku, 2026-10-15): the format `dilemma-thriller` on the same page (`brands/dilemma-table.json`, `alsoFormats`), the writing rules `prompts/dilemma-thriller.md`, and what is different (told from inside the danger, the Trainer as a voice, a clock, two cliffhangers, nothing violent shown, made in both shapes) in `knowledge/playbooks/formats/dilemma-thriller.md`, read with the game theory playbook.

Reusing a library asset in a new pose or expression needs no full guide read, but its stills still go through the Style Check.

## Repository layout and commands

- `shared/` Zod schemas shared by every part. `engine/` Remotion (React, TypeScript). `cli/` orchestrator. `audio/` Python workers managed by uv.
- `npm run doctor` reports every tool version. `npm run bench` renders the test scene and measures speed.
- `npm run look-test -- --all` builds the Phase 1 look test (voice, stills, video, style match sheets); `--audition` speaks the audition lines in every American English Kokoro voice. Each stage runs alone too.
- Voice: `cd audio && uv run python -m studio_audio.voice synth --script <voice-script.json> --out <dir>` writes `voice.wav` and `timings.json` (contract in `shared/src/voice.schema.ts`). Kokoro 0.9.4 gives word timestamps itself.
- Script: `npm run script -- new --run=<name> --mode=<as-is|refine|original> [--format=] [--from=<Biku's script>] --request="..."` makes `runs/<today>-<name>/` with his request and his script untouched. Claude then writes `script.json` (the words, who says them, each line on a beat of the format; contract in `shared/src/script.schema.ts`). `chapters --run=` splits it into parts of at most a minute, `check --run=` holds it to its mode's rules (as-is: word for word; refine: every change listed, every number kept, none invented; original: sources for factual formats), and `page --run=` writes `script.md` for Biku. The writing rules are in `knowledge/playbooks/general.md`; a file in `prompts/` replaces them.
- Shot plan: `npm run plan -- menu` lists everything a shot can use by name. `draft --run=` lays the checked script out as `storyboard.json` (scenes, lines, words cut into shots of 2 to 4 seconds) with every decision marked "todo"; Claude then decides each scene's place and each shot's people, poses, faces, camera and sound. `check --run=` runs every check (names against the library, staging rules, word for word against the script), `needs --run=` is the library check (what the video uses and what must be drawn first), and `page --run=` writes `storyboard.md`, the shot list Biku reads, ending with the feeling plan (each person's line of feeling, scene by scene, every change with its shot and its words). The planning rules are in `knowledge/playbooks/general.md`.
- Build a part: `npm run make -- --run=<run> --part=<n> [--size=16:9|9:16|4:5] <stages>` builds one part of a video from the storyboard into `runs/<run>/part-<n>/`. Stages: `--voice` (Kokoro speaks the part's lines), `--time` (the voice's times go into the shots), `--sound` (music and effects from the storyboard, mixed under the voice), `--stills` (one still per shot, sheets of them all, and `colours-<shape>.png`: the first still of each scene in a row, the colour plan at a glance), `--animatic` (the rough timed storyboard: each still held for its shot's length with the sound, made in seconds, numbered, in `part-<n>/animatic/`; needs `--stills` and `--sound`), `--preview` (a half-size video to check first, numbered like the finals, in `part-<n>/preview/`), `--video` (the part as a video; each render gets the next version number), `--resound` (the newest finished video with the sound as it stands, the pictures kept as they are: for a change of sound only, in seconds; refused if the pictures changed), or `--all` (everything but the preview). `--clip=9-15` renders only those seconds at full size into `part-<n>/clips/`, to look closely at one moment. It refuses a plan with a problem in it or something the builder cannot put on screen. Look at the sheet of stills before rendering the video. Left out, the size is the brand's first.
- Self-check: `npm run qa -- --run=<run> --part=<n> [--size=]` checks the newest video of a part (Part 2, section 12). It measures the file, the sound and every frame of the pictures, runs the plan's own checks again, and cuts a strip of frames across every move and every change of shot into `part-<n>/qa/<video>/`. Claude then looks at every still (Style Check and story check) and every strip, and writes what it saw in `part-<n>/qa-look-<shape>.json`; a look at an older render does not count. It writes `part-<n>/qa-report-<shape>.md`, the page Biku reads, and ends with an error while anything is left to fix. Run it after `--video` and before showing a part. With `--preview` it checks the preview. A look taken at another render of the part (its preview, or an earlier final) stands for this one when every frame is measured to show the same picture, so: preview, check and look, then `--video` and check again.
- Output: `npm run output -- --run=<run> [--sizes=16:9,9:16] [--vertical=full|teaser] [--cover=side|words|ribbon|band]` makes the finished files of a video in `runs/<run>/out/` and writes `runs/<run>/delivery.md`, the page that says what to upload where. The shapes are the page's usual ones (the brand file), or the ones given here, which are then kept in the run's `run.json`; the vertical shape is the whole video or a teaser (part 1 alone). For each file it takes the newest video of every part in that shape (each must have passed `npm run qa` as that very video), mixes the sound once for the whole video (`runs/<run>/cuts/<kind>/`), joins the pictures (dark before a part that opens on a fade), adds the brand's closing card when there is one, writes one captions file, draws the cover (the storyboard's `cover` names the shot) and checks the finished file. Claude then looks at the strip across each join and at the cover (`out/look/<name>/`) and writes `out/<name>.look.json`. Nothing is written over: each file takes the next version number.
- Storyboard: `npm run storyboard -- plugins` lists and checks every format, brand, voice and saved character. `npm run storyboard -- check --run=<run>` (or `check <file>`) checks a storyboard: its shape, that every name in it exists in the library and the plug-ins, that its scenes follow the format's beats, and the length of each chapter. A video is built in chapters of at most 60 seconds; each chapter is shown to Biku in the phone size and the next one starts only when he says so.
- Sound: `npm run sound -- list` names every mood and effect; `samples` and `reel` write the listening files to `runs/2026-10-06-sound-test/out/`; `mix --run=<run>` mixes a run's voice with its `sound-plan.json` (which mood starts when, which effect happens when) into `audio/mix.wav` and `audio/mix.json`; `check` fails unless everything is at -14 LUFS with the true peak at or below -1 dB. `npm run short -- --run=<run> --sound --video` mixes and renders. A file in `music/` or `sfx/` named after a mood or effect replaces the studio's own. Claude cannot hear: judge sound by the measured report and tell Biku it needs his ears.
- The instrument set for the music is not in git. Get it once with `cd audio && uv run python -m studio_audio.soundfont fetch` (32 MB, into `audio/soundfonts/`).
- Library: `npm run library -- search <words>` finds assets by tag, music moods and sound effects included (`--kind=costume` narrows it), `list` and `show <id>` print the index, `characters` lists the saved character cards, `sheet <character>` draws a saved character's three pictures into `characters/sheets/` (the character sheet, the faces, the poses), `cast <series> [--order=id,id]` draws every character of one cast together at the game table, `look <id>` renders one asset in three views on light and dark for the draw, look and fix loop, `stills` writes the golden stills in `knowledge/golden/assets/`, `catalog` renders the picture catalog in `library/catalog/`, and `check` fails if anything drawn is missing from the index. `/draw <description>` runs the whole loop for a new asset.
- `npm run sheets` renders the sandbox contact sheets for the draw, look and fix loop (`--only=poses`, `--video`, `--golden`). Look at them before calling any drawing done.
- `npm test`, `npm run typecheck`, `npm run lint`, `npm run format` must pass at the end of every phase.
- Python: `cd audio && uv run pytest` and `uv run python -m studio_audio.doctor`.
- Every command that draws goes through `cli/src/render.ts` (one shared browser) and keeps its scratch files in `.cache/tmp/` inside the project, deleted when it ends. Never call the renderer directly from a new command, or its leftovers pile up in the system temporary folder on drive C.
- Node is a loose binary at `F:\node.exe`. ffmpeg, espeak-ng, uv and fluidsynth are Scoop installs under `~/scoop`. espeak-ng needs `ESPEAK_DATA_PATH`, which Scoop set as a user variable.
